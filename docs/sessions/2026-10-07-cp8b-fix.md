# Session 2026-10-07, fix 2.12.1 (typing in a card field)

**Cause.** RN web renders a Pressable with role "button" as a native <button>. The task card was one, and the Notes textarea (and the other fields) sat inside it. Chrome treats a Space typed in a field inside a <button> as a click on the button, so the card's press handler toggled it closed. (Enter had a related path through RN web's press handler, which fires onPress when a key is released.)

**Fix.** The card root is no longer a role button element (it keeps its label); its press handler ignores events whose target is an editable element (`lib/editable.ts`, `isEditableTarget`, also used by the drag start check); the rename box sits in its own press wrapper like the expanded body, so Enter there never toggles the card. Escape in Notes blurs it (saving) and focuses the card; a second Escape on the card collapses it. The card also gets `tabIndex -1` for that.

**Tests.** `lib/editable.test.ts` (3). Real keyboard and pointer check `npm run test:real:cp8c` (24 checks, isolated temp folder asserted): real keyDown, char and keyUp for every character, so a key handler up the tree sees what a keyboard sends. Notes ("hello world with spaces", Enter, Backspace, arrows, Escape twice, saved on blur), Add subtask, a subtask title, the title rename, the label search, the filter search, the repeat day of month field, and the custom duration popover. The harness now lets smooth scrolling settle before it clicks (a click right after scrollIntoView was missing its target in the cp8b and cp8c runs). All earlier real checks pass (cp8b 59 and 2, cp6 61 and 60, cp7 19 and 2).
