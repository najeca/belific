# Session 2026-10-05, checkpoint 2b (corrections to the task and week flow)

Product rules from Jethro that override the checkpoint 2 choices: tasks are created only in the Brain Dump pane; the pipeline is Brain Dump, task details, Plan (week board), Timebox; the board only goes forward from today; recurrence is set in the Brain Dump form only.

## Commit 1 (2.4.1): creation only from Brain Dump

### What changed
- The kanban no longer creates tasks: the "+" in every column header is gone (checked: zero matching elements in the running app). Clicking a card still edits an existing task.
- Brain Dump pane header has a "New task" button that opens the task form blank. "Make task" on a row still opens it pre-filled and removes the item on save; from the blank button there is nothing to remove.
- The form's Day (create and edit) is a web date input with `min` set to today. A past date typed into the field is rejected; a future date is accepted.
- `TaskModalState` for a new task no longer carries a Day (the kanban used to pass one).

### Choices where the prompt was silent
- Editing a task that already has a past Day keeps that stored Day until the user changes it; the picker will not offer a past date. (Planned and approved.)
- "+ Label" stays in the form. **Open question for Jethro:** should labels also be creatable only in one place (for example a Labels page), or is an inline "+ Label" in the task form fine long term?

### Gates
- `tsc --noEmit` clean, iOS JS bundle export succeeded, `node --test` on mobile and desktop passed (counts in the final report).
- Visual check (throwaway script, not committed): the Brain Dump header shows "New task", the blank form shows the Day field, the form rejected 2020-01-01 and accepted 2099-01-01.

## Commit 2 (2.5.0): forward-only week board

### What changed
- `lib/kanban.ts`: `weekStartOf` (Monday based, `WEEK_STARTS_ON` is the one constant), `addWeeks`, `weekDays` (the current week is today to Sunday, future weeks Monday to Sunday), `formatWeekLabel`, `clampToToday`, `isDayInView`. `bucketTasks` lost the "later" bucket and now only fills the days it is given; overdue tasks join Today only while Today is displayed.
- `KanbanPane.tsx`: pinned Unscheduled column plus a horizontally scrolling set of day columns; week header with 44px previous and next arrows (previous disabled on the current week), the label, a "This week" button and a "Jump to week containing" popover (date input, min today). The "Later" column is gone. "Move to day" offers Unscheduled, Today, Tomorrow and a date input (min today) and shows "Moved to <day>" for six seconds when the target is outside the displayed week.
- Column width 224 px (from 248) so more day columns fit beside the pinned column.
- Timebox day navigation untouched.

### Tests
49 tests in `mobile/lib` (was 37): week start across Monday, Sunday, year and leap boundaries, `weekDays` for current and future weeks, label formatting across month, year and leap boundaries, `clampToToday`, bucketing for an arbitrary week, and 40 consecutive week additions in five time zones (London, New York, Lord Howe, Auckland, Kolkata) checking each result is a Monday at midnight exactly seven calendar days later.

### Visual check
Throwaway script outside the repo; it shifts the page clock two days forward (through the Chromium debugger) so the app believes it is Wednesday 7 October, because real today is a Monday. Checked and read: current week shows Today, Tomorrow, Fri, Sat, Sun with Mon and Tue hidden, previous arrow and "This week" greyed out; next week shows Mon 12 to Sun 18 Oct with previous enabled; jumping to a date in November lands on "Mon 2 Nov to Sun 8 Nov" with the right task; the Move menu shows Unscheduled, Today, Tomorrow and a date field; moving a task to 6 Nov showed "Moved to Fri 6 Nov" and the card left the column; the finished past task is not shown; "from 2 Oct" shows on the overdue card.

### Choices where the prompt was silent
- The jump and move date inputs are controlled with an empty value, so each pick acts immediately and the field resets.
- If the app is left open past Sunday the displayed week never falls behind the real current week.
- The week label always shows the first rendered day to Sunday, so on a Sunday it reads "Sun 11 Oct to Sun 11 Oct".
- The "Moved to ..." line is plain muted text above the board for six seconds; it pushes the board down a little while shown.
- Past days inside a future week cannot exist, so no extra rule was needed there.
