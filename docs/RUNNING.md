# Running Belific

Every command below comes from the repo's `package.json` scripts and docs (`desktop/README.md`, `docs/BELIFIC_EAS_TESTFLIGHT.md`, `TESTING_PROTOCOL.md`, `docs/NEW_PROJECT_SYNC_TEST.md`). Where the repo does not say, this file says so. Run everything from the repo root unless a `cd` is shown. Node is not pinned in any `package.json`.

## 1. Keys you need (read this first)

The app needs two values, both in `mobile/.env` (gitignored; there is no `.env.example` in the repo, so create the file yourself):

```
EXPO_PUBLIC_SUPABASE_URL=<project URL>
EXPO_PUBLIC_SUPABASE_ANON_KEY=<publishable key>
```

- Where they come from: the shared Supabase project `vlogfwnmaqorhialcqbr`, dashboard, Project Settings, API (the URL is `https://vlogfwnmaqorhialcqbr.supabase.co`; the key is the publishable one, it starts `sb_publishable_`). Or copy `mobile/.env` from your other computer. They are compiled into the app, so they are public by design. Never put the service role key anywhere in the app.
- Without them the app throws "Missing EXPO_PUBLIC_SUPABASE_URL / EXPO_PUBLIC_SUPABASE_ANON_KEY" at launch (`mobile/lib/supabase.ts`).
- The desktop reads `mobile/.env` when it builds the web export. The iPhone TestFlight build does **not**: EAS cannot read `.env`, so the same two names must be EAS environment variables (section 4).
- No other key is needed to run the apps. Apple and Google sign in were set up in the Supabase, Apple and Google dashboards (`docs/APPLE_SIGNIN_SETUP.md`, `docs/GOOGLE_SIGNIN_SETUP.md`); nothing for them goes in the repo.

## 2. Windows desktop, from a fresh clone

1. `git clone <repo>` then `git checkout v2-redesign`.
2. Create `mobile/.env` (section 1).
3. Install both folders (the desktop script exports the Expo app from `mobile/`):
   ```
   cd mobile
   npm install
   cd ../desktop
   npm install
   ```
4. Start it: `npm run desktop` (in `desktop/`). It runs `expo export --platform web` into `mobile/dist`, then opens Electron on it. The first run needs internet.
5. Your data is in `%APPDATA%\belific-desktop` (`data\`, `backups\`, `logs\main.log`). It works fully signed out.
6. Developing (hot reload): in `mobile/` run `npm start`, then in `desktop/` run `npm run desktop:dev`. It uses a separate `belific-desktop-dev` data folder.

If it fails:
- "Missing EXPO_PUBLIC_SUPABASE_URL...": `mobile/.env` is missing or misspelt (step 2).
- The export step fails: run `npm install` in `mobile/` again, then `node scripts/build-web.js` in `desktop/` to see the error by itself.
- The window opens but nothing loads: `mobile/dist` is empty or stale; run `npm run desktop` again (it rebuilds).
- `electron` is not found: `npm install` in `desktop/` did not finish (it downloads Electron).
- Read `%APPDATA%\belific-desktop\logs\main.log` (no personal content).
- Checks: `npm test` in `desktop/` and in `mobile/` (plus `npx tsc --noEmit` in `mobile/`).

## 3. Windows installer

The repo supports it (unsigned, per user, no auto update):

```
cd desktop
npm install
npm run dist
```

Output in `desktop/dist` (git ignored): `Belific-Setup-<version>.exe` and `win-unpacked/Belific.exe`. `npm run dist -- --dir` builds only the unpacked app. Needs internet the first time and a Windows PC. SmartScreen says "Windows protected your PC": More info, Run anyway. Installing over an older version keeps your data.

## 4. iPhone

This Windows PC cannot build for iOS. The repo documents two routes.

**Development (needs a Mac):** `TESTING_PROTOCOL.md` section 1 uses a local USB build, never Expo Go (the repo does not document Expo Go, and the app uses native modules: Apple sign in, notifications, calendar):

```
cd mobile
npm install
npx expo run:ios --device <your device id> --configuration Release
```

`mobile/package.json` also has `npm start` (`expo start`) and `npm run ios` (`expo run:ios`). There is no committed `ios/` folder; it is generated by the command. Unverified from here: any Mac or Xcode setup details.

**TestFlight build (EAS).** Never run these without Jethro saying "ready for EAS build" (`TESTING_PROTOCOL.md` section 2); EAS iOS builds are limited to 15 a month. eas-cli 18.8.1 is what the repo was checked against. Run in `mobile/`:

1. `eas whoami` shows the owner `jetmakes`.
2. `eas env:list --environment production`. If the two `EXPO_PUBLIC_SUPABASE_*` variables exist they may hold the **old** project: update them, do not add duplicates. Set or update with `eas env:create` or `eas env:update` (run `--help` for the exact flags first; the doc marks the spelling unverified): `EXPO_PUBLIC_SUPABASE_URL` = the project URL, `EXPO_PUBLIC_SUPABASE_ANON_KEY` = the publishable key (plaintext or sensitive, not secret). Read the URL back with `eas env:list --environment production`. Values are compiled in at build time.
3. Make a fresh encrypted device backup of the iPhone first (it holds the only unsynced copy of its data).
4. Before the first upload of a version, check in App Store Connect that this version and build number are unused.
5. Build: `eas build --platform ios --profile production`
6. Upload: `eas submit --platform ios --profile production` (it asks for the App Store Connect app and Apple sign in), or download the `.ipa` and use Transporter.
7. In App Store Connect, add the build to an **internal** group only, install from TestFlight. Never an external group, never submit for review.

**Raise the build number:** edit `expo.ios.buildNumber` in `mobile/app.json` by hand (currently `"1"`; there is no `autoIncrement`). A build number must be unique within a version: `"1"`, then `"2"`, and so on; a new version string starts again at `"1"`. Commit it, then build again. The current version is 2.25.0 (it adds `expo-calendar`, a native module, so the calendar part needs a build made after that change).

## 5. Sign in and check sync

Sign in only with an account you are happy to use (the first sign in uploads this device's local data). For a first test use a throwaway Google account (`docs/NEW_PROJECT_SYNC_TEST.md`).

1. **Desktop:** profile icon (top right), Sign in, **Continue with Google**, finish in the browser. Back in the app the icon shows your initial. If this computer already has data, it asks what to do with it (upload, or start empty with a backup). Apple on the desktop needs `docs/APPLE_SIGNIN_SETUP.md` first and was failing at last note (`docs/CURRENT_TRUTH.md`).
2. **iPhone (TestFlight build):** Settings, Account, **Sign in with Google** (Safari opens, then returns to Belific) or **Sign in with Apple**. Use the same Google account as the desktop.
3. **Check on the desktop:** Settings, Sync shows the status, last synced and any error; **Sync now** forces one. The profile menu shows the same.
4. **Check across devices:** create a task `sync test` on the desktop, press Sync now. On the phone, bring the app to the foreground (it syncs then, and every 120 seconds while open): the task appears in Tasks. Change it on the phone, then Sync now on the desktop: the change appears.
5. **Check on the server (optional):** dashboard, Table Editor, schema `belific`, table `tasks`: a row with that title and your user's id; a deleted task stays as a row with `deleted_at` filled.
6. The phone shows **no** sync status of its own; if something does not arrive, look at the dashboard and the desktop's Settings, Sync.
7. Signing out on the phone does not sign out the desktop.
