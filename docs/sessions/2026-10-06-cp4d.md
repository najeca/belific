# Session 2026-10-06, checkpoint 4.3 (repeat rework, labels)

Version 2.8.3. Repeat simplified, ready made labels, label rename and delete, no duplicate names.

## 1. Repeat, simplified
- The choices are Does not repeat, Weekly, Every 2 weeks and Monthly. "Specific days" and "Every day" are gone as separate choices.
- Weekly and Every 2 weeks show the seven day chips (1 to 7) plus the Weekdays and Weekends buttons.
- **Weekly with all seven days**: the chip reads **Daily**, the summary reads "Repeats every day", and it is stored as the existing `daily` kind with no days. Unticking any day makes it Weekly again, stored as `weekly` with days. A stored `daily` task opens as Daily with all seven chips on.
- **Every 2 weeks** never becomes Daily; with all seven days it reads "Repeats every day of every other week".
- **Monthly**: one "Day of the month" number field (a web `<input type="number">`, 1 to 31). It defaults to the stored `recurrenceMonthDay`, else the task's Day number, else 1. The summary reads "Repeats on the 1st of every month"; for 29 to 31 it adds "In shorter months it falls on the last day." Anything other than a whole number from 1 to 31 shows "Enter a day from 1 to 31" and disables Save.
- Unchanged from 4.2: the summary line, the "starts …" adjustment, legacy handling and every next-occurrence rule.
- `lib/repeat.ts` gained `repeatLabel`, `ruleFor`, `allSeven`, `initialDays`, `parseMonthDay`, `defaultMonthDay` and `alignToMonthDay`. `resolveRepeat` and `repeatSummary` now take the month day number instead of a stored value.

### Choices where the brief was silent (repeat)
1. **Monthly also moves the Day**, like Weekly: if the task has a Day on another date, it moves to the first date on or after it with the chosen number (clamped), and the summary says "starts Sun 1 Nov". A Day-less monthly task stays Day-less.
2. **The stored month day now always wins** in `monthDayOf` once set, because it is an explicit field. In 4.2 it only won while the Day still matched it, and one 4.2 test assertion was updated accordingly. Older monthly tasks without the field still use their Day's number.
3. Weekly with all seven days keeps the task's Day as it is (every day matches), so there is no "starts".
4. Switching to Weekly or Every 2 weeks with no days chosen still preselects the weekday of the Day (from 4.2).
5. The Repeat chips have accessible names "Repeat Weekly", "Repeat Monthly" and so on, so the Weekly chip is still findable while it reads Daily.
6. The month field accepts "07" as 7. It rejects blanks, 0, 32, decimals, negatives and exponents.

## 3. Label management and duplicates
- `lib/labelRules.ts` (pure): `normalizeName`, `findLabelByName`, `availableSuggestions`, `renameProblem` and `deletedLabelTarget`. Names compare trimmed and case insensitively, and deleted labels never count.
- `lib/labels.ts` (desktop only) gains the actions:
  - `createLabel` returns the existing label for a duplicate name instead of adding one; the editor then says `Using the existing label "Gym"`.
  - `renameLabel` rejects a blank name or another label's name.
  - `deleteLabel` moves or clears the label's tasks through `updateTask`, then tombstones the label.
- `lib/storage.ts` gains two functions. `updateProject` stamps `updatedAt` and pushes through `pushLater(sync.pushProject)`, the same path as `addProject`. `deleteProject` is a tombstone: `deletedAt` and `updatedAt` set, saved, and pushed the same way. These are the first project update and delete paths; the comment saying "No delete path exists for Project yet" was replaced.
- Editor: the selected label shows Rename and Delete label next to its swatches.
  - Rename opens an inline field that saves on Enter; a duplicate shows "Another label already has that name" and the field stays open.
  - Delete uses the inline confirm, e.g. `Delete this label? 2 tasks use it; they move to the other "work". Yes / No`, or "…; they will have no label.", or "No tasks use it."
- Jethro's two same-named labels: deleting either moves its tasks to the other.

### How the sync and iOS safety was checked (conditions 1 to 3)
- **A tombstoned project is pushed:** `lib/sync.ts` `pushProject(p)` calls `pushRow('projects', projectToRemote(p))`, and `projectToRemote` maps `deleted_at: p.deletedAt ?? null`. `syncTable` keeps the row with the newer `updatedAt`, tombstones included, and uploads newer local rows. Because `deleteProject` stamps `updatedAt` with the delete time, the tombstone wins the merge. `sync.ts` is unchanged.
- **Deleted projects never appear on the iPhone:** every iOS project list goes through `loadProjects()`, which returns `all.filter((p) => !p.deletedAt)`. A search of `app/` and `lib/` found exactly two: the Tasks screen filter chips (`app/tasks.tsx`) and the Task form picker (`app/components/TaskForm.tsx`). The other "project" matches in `lib/data.ts` and `lib/ownerSeed.ts` are an event category, not Projects. Tasks are moved or cleared before the tombstone, so no task is left pointing at a deleted label.
- **iPhone code unchanged:** the new actions are only imported by `components/desktop/TaskModal.tsx`, and the iOS bundle marker search (drag marker, "Jump to week containing", "Past day") passes at 0. The new storage functions are in the shared `storage.ts` but are called only from desktop code.

### Choices where the brief was silent (labels)
1. A rename is a real edit (`updatedAt` stamped and pushed), because `name` is a synced field; colour changes stay silent local writes (4.1).
2. Deleting the label selected in the editor makes the editor's selection follow the same rule (the same-named label, or None), so Save cannot re-attach a deleted label.
3. The confirm counts live tasks with that label, completed ones included (they are edited too); deleted tasks keep their old key.
4. Losing focus closes the rename field without saving. Escape closes the whole editor, as everywhere in it.
5. Suggestions show with a "+" prefix and a "Suggested" caption; they never show for a name a deleted label had once, unless no live label has it.

## Bug found and fixed by the real input check
- **A rejected rename closed its own field.** React Native's single line input blurs on Enter by default, and the field closes on blur, so after a duplicate name the error showed but the field was gone. Fixed with `blurOnSubmit={false}`.
