# Session 2026-10-05, checkpoint 2b (corrections to the task and week flow)

Product rules from Jethro that override the checkpoint 2 choices: tasks are created only in the Brain Dump pane; the pipeline is Brain Dump, task details, Plan (week board), Timebox; the board only goes forward from today; recurrence is set in the Brain Dump form only.

## Commit 1 (2.4.1): creation only from Brain Dump

### What changed
- The kanban no longer creates tasks: the "+" in every column header is gone (checked: zero matching elements in the running app). Clicking a card still edits an existing task.
- Brain Dump pane header has a "New task" button that opens the task form blank. "Make task" on a row still opens it pre-filled and removes the item on save; from the blank button there is nothing to remove.
- The form's Day (create and edit) is a web date input with `min` set to today. A past date typed into the field is rejected; a future date is accepted.
- `TaskModalState` for a new task no longer carries a Day (the kanban used to pass one).

### Choices where the prompt was silent
- Editing a task that already has a past Day keeps that stored Day until the user changes it; the picker will not offer a past date. (Planned and approved.)
- "+ Label" stays in the form. **Open question for Jethro:** should labels also be creatable only in one place (for example a Labels page), or is an inline "+ Label" in the task form fine long term?

### Gates
- `tsc --noEmit` clean, iOS JS bundle export succeeded, `node --test` on mobile and desktop passed (counts in the final report).
- Visual check (throwaway script, not committed): the Brain Dump header shows "New task", the blank form shows the Day field, the form rejected 2020-01-01 and accepted 2099-01-01.

## Commit 2 (2.5.0): forward-only week board

### What changed
- `lib/kanban.ts`: `weekStartOf` (Monday based, `WEEK_STARTS_ON` is the one constant), `addWeeks`, `weekDays` (the current week is today to Sunday, future weeks Monday to Sunday), `formatWeekLabel`, `clampToToday`, `isDayInView`. `bucketTasks` lost the "later" bucket and now only fills the days it is given; overdue tasks join Today only while Today is displayed.
- `KanbanPane.tsx`: pinned Unscheduled column plus a horizontally scrolling set of day columns; week header with 44px previous and next arrows (previous disabled on the current week), the label, a "This week" button and a "Jump to week containing" popover (date input, min today). The "Later" column is gone. "Move to day" offers Unscheduled, Today, Tomorrow and a date input (min today) and shows "Moved to <day>" for six seconds when the target is outside the displayed week.
- Column width 224 px (from 248) so more day columns fit beside the pinned column.
- Timebox day navigation untouched.

### Tests

### Choices where the prompt was silent
- The jump and move date inputs are controlled with an empty value, so each pick acts immediately and the field resets.
- If the app is left open past Sunday the displayed week never falls behind the real current week.
- The week label always shows the first rendered day to Sunday, so on a Sunday it reads "Sun 11 Oct to Sun 11 Oct".
- The "Moved to ..." line is plain muted text above the board for six seconds; it pushes the board down a little while shown.
- Past days inside a future week cannot exist, so no extra rule was needed there.

## Commit 3 (2.6.0): recurring tasks

### What changed
- `Task.recurrence?: RecurrenceRule` and `Task.recurrenceDays?: WeekDay[]` (the existing `CustomEvent` types). **Local only** until the sync migration (checkpoint 5); `sync.ts` is untouched.
- Form: a Repeat control (Does not repeat, Daily, Weekly with weekday chips, Every 2 weeks, Monthly). Field order is now name, duration, priority, label, notes, Day, Repeat, as in the prompt. Weekly with no weekday selected means every 7 days; "Every 2 weeks" ignores weekday chips.
- `lib/recurrence.ts` (pure): `nextOccurrence`, `nextOccurrenceId`, `rootTaskId`, `buildNextOccurrence`.
- `lib/taskActions.ts`: the ONE shared function `setTaskCompleted(task, completed)`. Called by the kanban checkbox and the task form's Done toggle. It lives in `mobile/lib` (not a desktop file) so iOS can call it.
- Recurring cards show a small repeat icon. The board creates nothing.

### To-do for checkpoint 5 (also in docs/CURRENT_TRUTH.md and the review's checkpoint 5 row)
The iOS app must complete tasks through `setTaskCompleted` once sync lands, and the sync mappers and migration 2 must carry `recurrence` and `recurrenceDays`. Without that, a recurring task completed on the phone never creates its next occurrence.

### Tests
64 tests in `mobile/lib` (was 49). The 15 new ones cover daily across month, year and leap boundaries; weekly with and without weekdays (Monday to Thursday, Thursday wrapping to Monday, an unselected weekday, a single weekday equal to the Day, Sunday wrap, across the year and a leap day); every 2 and 3 weeks; monthly clamping (31 Jan to 28 Feb, 31 Jan 2028 to 29 Feb, 31 Mar to 30 Apr, 31 May to 30 Jun, 31 Dec to 31 Jan, 29 Feb 2028 to 29 Mar); no Day or an invalid Day counts from today; the result is independent of today; clock changes in five time zones; id determinism and the root rule; and `buildNextOccurrence` copying the right fields.

### Choices where the prompt was silent (the first three are the ones planned and approved)
- The root id is the part of the id before the first ":" (existing UUID and timestamp ids never contain one).
- Editing a task that already has a past Day keeps it until the user changes it.
- Un-completing a task does not remove an already created next occurrence.
- The next Day is computed from the task's own Day only (never from the day it was completed), so every device computes the same id. Consequence: completing a task that was already overdue creates a next occurrence that may itself be in the past; it then shows first in Today as carried over. **Open question for Jethro:** should a late completion skip forward to the first date on or after today? That would make ids depend on the completion day, so two devices could disagree.
- Monthly clamping is not remembered: 31 Jan becomes 28 Feb, then 28 Mar, 28 Apr (the day drifts down once clamped).
- The time of day (`startTime`) and `origin` are not carried to the next occurrence, because the prompt listed name, duration, priority, label, notes and repeat settings.
- The form's Done toggle (edit mode) was added so the form is a completion point as well as the kanban checkbox. The Timebox has no completion control for placed tasks today; any added later must call `setTaskCompleted`.
- Creation of the next occurrence is serialised inside `taskActions.ts` (a promise chain) so a double click cannot read "not there yet" twice.
- "Every 2 weeks" uses the existing `biweekly` value; `triweekly` stays in the type but is not offered.
