# Session 2026-10-07, 2.13.0 (checkpoint 8.3: duration chip, dropdown, Estimated and Actual)

**What changed.**
- `mobile/lib/duration.ts`: new `parseDuration` (the eight typed forms, 1 to 1440, `allowZero` for a corrected Actual), `formatClock` (chip H:MM), `formatHM` and `formatSecondsHM` ("1h 30m"), `DURATION_PRESETS` and `presetLabel`. The old picker helpers (steps, Custom, `splitDuration` and so on) are removed; nothing else used them.
- `mobile/lib/timer.ts` (pure maths from timestamps, 12 hour threshold, prune) and `timerController.ts` (the rules with the clock, store and tasks injected). `taskTimer.ts` binds them to `kv` key `belific_timer` (not synced, also cleared by `clearAllData`). `taskActions.ts`: completing stops the timer (desktop only), dropping as a subtask discards it; `taskOps.ts`: delete discards it. `DesktopHome` prunes at startup.
- `TaskCard`: chip as H:MM with the start time as separate muted text, running dot, `TimerRow` (play/pause, Actual, Estimated, inline forgotten-timer prompt). `TaskPopovers` `DurationBody` rewritten as field plus presets. `TaskBlockPopover` row reads `0:15, starts 09:30`.
- Sync: `Task.actualSeconds`, mapper column `actual_seconds` (`sanitizeActual`), `Caps.taskActual`, probe, `preserveFieldsFor`, `hasActualValues` and the engine's flip-and-queue. Migration `20261007130000_task_actual_seconds.sql` and its rollback written, NOT applied; no database was contacted.

**Choices to know.**
- Chip layout for a placed task: the start time is its own small muted text left of the chip. A single "09:30 · 0:15" string made two H:MM values read as one.
- Starting another task while a >12h timer runs asks about the old one first (on the card where Start was pressed) and starts nothing until answered.
- Completing a task whose timer ran over 12 hours drops that run without adding it (nobody to ask).
- A typed Actual while the timer runs is the total shown: the stored part is the typed value minus the running time.
