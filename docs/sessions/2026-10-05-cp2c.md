# Session 2026-10-05, checkpoint 2c (the thing you capture IS the task)

Jethro's new flow (replaces "Make task" and "New task"): "the user adds the thought of what needs to be done first in the brain dump, and then they can edit afterwards and add the extra detail like how long it is, when it is, etc." Brain Dump is not a notes app and not a separate step before tasks.

## What changed (2.7.0)
- Desktop capture: Enter in the Brain Dump input creates a Task right away (title only, no Day, `origin: 'dump'`). `createThought` in `lib/taskActions.ts`, builder `newThought` in the pure `lib/thoughts.ts`.
- The left pane lists every incomplete task with no Day (newest first) plus legacy `BrainDumpItem`s shown identically (`splitThoughts`). Completed tasks are hidden; a collapsed "Done today (n)" line at the bottom lists Day-less tasks completed today (local day), each with a checkbox to undo.
- Clicking anywhere on a row opens the editor; a small pencil shows on hover as an affordance. Same for a kanban card. The editor (`TaskModal.tsx`) now edits only: name, duration chips, priority, label, notes, Day, Repeat, Done, delete with an inline confirm. It has no create mode.
- A legacy item opens in the same editor. Saving, with or without edits, converts it into a Task (`convertDumpItem`: write the Task, then delete the item; title, notes and original creation time carry over) and removes the item. Cancelling leaves it untouched. Deleting in the editor deletes the item.
- Setting a Day takes a task off the list and onto the board; clearing it (editor or the card's "Remove day" hover button, which also clears `startTime`) puts it back. Move to day now offers Remove day, Today, Tomorrow and a date input. Past dates still cannot be chosen.
- The Unscheduled column is removed from the board (`bucketTasks` no longer returns it). "Make task" and "New task" are removed.
- `setTaskCompleted` now counts the next occurrence from the later of the task's Day and today (in `nextOccurrence`), so an overdue recurring task completed today never produces a past-dated next occurrence. A recurring Day-less task counts from today.
- iPhone: untouched (`BrainDumpItem`, its screens, `storage.ts`, `sync.ts` unchanged). The iOS bundle gate passes.

## The edit failures: root causes (found with real pointer input)
Method: a throwaway script outside the repo drives the real app through the browser input pipeline (the same mechanism Playwright's `page.mouse` uses): real pointermove, down and up and real key events, not DOM `.click()`. Earlier checks used DOM `.click()`, which bypasses all of this, so none of these showed up.
1. **Only the title text was a click target.** On the previous build a real click on a card's meta line (label or duration) did nothing, and on rows only the title line responded. Anything that was not squarely on the title looked dead. Now the whole row or card is the target.
2. **Hover-only buttons disappeared under the pointer.** react-native-web's `Pressable` ends the parent's hover as soon as the pointer enters a nested pressable. The cards' and rows' action buttons were rendered only while hovered, so they unmounted the moment the pointer reached them, the click landed on the card or row instead, and moving back did not restore them. Fixed with `HoverPressable` (DOM `mouseenter` and `mouseleave`, which keep a parent hovered while the pointer is over its children).
3. **Escape did not close the editor while a field had focus.** react-native-web's `TextInput` stops keydown events bubbling, so the window-level listener never ran. The earlier claim "Escape closes" was not true. The listener is now in the capture phase (task editor and Timebox event editor).
Which of these Jethro hit as "could not edit after creating" is not certain; 1 and 2 are both consistent with it.

## Choices where the plan was silent (the five agreed ones first)
1. Left-list rows have a complete checkbox (Unscheduled is gone from the board). Ticking a legacy row converts it into a completed Task.
2. Deleting a legacy item in the editor deletes the item.
3. "Remove day" and clearing the Day also clear `startTime`.
4. A completed Day-less task is hidden from the main list and, with the agreed change, appears under "Done today" until the day ends.
5. A recurring Day-less task stays on the left list; completing it creates the next occurrence from today.
Other choices:
- Newest first uses `createdAt`; a converted item keeps its original `createdAt`, so it stays in place.
- Done today only lists tasks with no Day (a completed task with a Day stays on the board, struck through).
- Removing a Day from a card shows a quiet "Back in the Brain Dump list" line above the board for six seconds.
- Hover icons on cards are mouse-only (as before); the whole card is also a focusable button that opens the editor, where Day and time can be changed by keyboard.
- The "+ Label" link stays in the editor (still an open question for Jethro).
- The editor heading reads "Edit task" for both tasks and legacy items.

## Limits
- Two devices completing the same recurring task on different days could create two different next occurrences (the id now depends on today); accepted.
- Task fields remain local only until checkpoint 5.
