# Session 2026-10-05, checkpoint 1 (Electron shell, file store, Brain Dump)

## Built
- `mobile/lib/kv.ts` and routing of `storage.ts`, `ownerSeed.ts`, `devSeed.ts` and the Supabase session storage through it (2.1.1). iOS falls back to AsyncStorage, so nothing changes there.
- `desktop/`: Electron 44.5.1 and electron-builder 26.15.3 (exact pins). Main process serves `mobile/dist` over a privileged `app://belific/` scheme with a path traversal guard, an `index.html` fallback for routes, and a CSP header (`default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' <belific supabase host>`). `contextIsolation` on, `sandbox` on, `nodeIntegration` off, single instance lock, `will-navigate` and `window.open` blocked (https links go to the system browser), minimum width 1024. IPC is limited to four kv calls plus a version, and every handler checks the sender URL.
- File store: one `.kv` file per key under `userData/data/`, keys must match `^[A-Za-z0-9_.-]{1,128}$`, atomic temp-then-rename writes, queued per key. Failures are logged to `userData/logs/main.log` and thrown back to the caller.
- Backups: on launch and every 24 hours, `data/` is copied to `backups/YYYY-MM-DD/`, newest 14 kept. File menu: "Export data…" and "Open backups folder".
- `npm run desktop:dev` uses a separate `-dev` userData folder (never real data) and loads `http://localhost:8081`.
- `BrainDumpPane.tsx` (2.2.0) and a shared refresh counter in `DesktopHome.tsx`.

## Headless smoke test (throwaway script outside the repo, not committed)
Launched the real app with a temporary userData folder and captured the window with `capturePage()`.
- App loaded from `app://belific/` with the bridge present (`kv`, `version`), `localStorage` empty (so nothing is going through the browser store).
- Seeded 3 items; the screenshot shows the three panes side by side, nothing overlapping, sage and cream colours matching `theme.ts`, the capture input pinned at the top, hairline dividers, a long item wrapping inside the pane.
- Typed text through real keyboard events (char then Enter): the item appeared at the top and was written to `belific_brain_dump.kv`.
- Relaunched a fresh process on the same folder: all 4 items were still there. A dated backup folder exists.
- Click a title: inline edit with the text selected, Enter saved it. Escape after typing left the title unchanged. Delete showed "Delete? Yes No" inline; No kept the item, Yes tombstoned it (`deletedAt` set, as on iOS).
- Fixed from the screenshots: the browser's default orange focus ring on the inputs is now the sage accent.

## Choices where the spec was silent
- A blurred edit saves (non-empty, changed text); an emptied title keeps the old one.
- Brain Dump rows show the title only; notes are not editable on desktop for now.
- `desktop/package.json` scripts run from the `desktop/` folder (`cd desktop` then `npm run desktop`).
- `window-all-closed` quits the app (tray comes with checkpoint 7).

## Limits of this verification
- Synthetic mouse moves did not make Chromium report `:hover` in the headless window, so the hover state was exercised by dispatching `pointerenter` events (the code path react-native-web listens to). Real mouse hover on a real window is therefore untested; Jethro should hover a row once.
- `app/components/` files are expo-router routes (gap N8): `/components/desktop/BrainDumpPane` exists as a route on web. Harmless now; move to `mobile/components/` when next touched.
