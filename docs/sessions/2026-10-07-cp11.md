## Built, in this order

1. **iOS marker script** `mobile/scripts/ios-markers.js`, `npm run check:ios-markers -- <export folder>`. Fails (1) on any marker in the Hermes bundle, and (2) on a missing folder or a folder with no `.hbc`. Markers: the earlier desktop names, `ProgressPage`, `seriesStreak`, `Show streaks`. One explicit allow list entry, `copyRoutineCompletions`; because Hermes de-duplicates strings, a bundle count cannot show use, so it is also checked in SOURCE with `git grep` (allowed only in `storage.ts`, `routineConvertActions.ts`, the script, tests). Tested in `iosMarkers.test.ts` (every marker fails, clean passes, missing folder and no bundle exit 2, the allowed name passes, an offender in source fails, the real repo passes). Decision 018 and CURRENT_TRUTH say `seriesStreak` is a marker only until the iOS catch-up release reuses it and that whoever ships it must remove the marker deliberately.
2. **`lib/seriesStreak.ts`** (pure). `seriesStreak({root, rows, legacyDates, todayKey})` returns null for a series that is not alive, else `current`, `best`, `done7/scheduled7`, `done30/scheduled30`, a 7 day `week`, `unit`, `repeat`. Treatment per day: scheduled and completed = done; scheduled, past, not completed = not done (ends the run); scheduled and tombstoned = skipped (neutral); today not done yet = open (neutral); not scheduled, before the series, future = off (neutral). Done = the occurrence is COMPLETED (ticking the last subtask completes it and completing ticks every subtask, so no second rule). For `rt_<id>` roots the old routine completions count as done days and, before the series' first row, every day is scheduled; nothing before the first known day counts as a miss. Wording lives in the same file (`streakLine`, `bestLine`, `windowLine`, `dayLabel`, `STREAK_TEXT`) so one test reads every string.
3. **Local tombstone retention** `series.keepsOccurrenceTombstone`, 400 days (was: only while the day is today or later). `storage.keepsSkip` uses it. Local only, no migration, the server never prunes. Tested, including that a kept tombstone beats an older live copy on a pull and is pushed again, and that a pruned one comes back from the server as a tombstone, with the skipped day neutral in the streak either way.
4. **UI:** `streakStore.ts` (computed once per refresh in `DesktopHome`, also after a sync and every minute), `StreakLine.tsx` (on TODAY's card only and in the block popover), `ProgressPage.tsx`, a Progress row in the profile menu (signed in and out), File, Progress (`menu:openProgress`, preload, `kv.ts`), the **Show streaks** switch in Settings, Planning (`showStreaks` in the main process settings, default true, validated, never synced).

## Decisions taken while building (flag for Jethro)

- **The line shows on today's card only**, not on the cards of the days ahead (a run belongs to today; "11 days in a row" on next Friday would be wrong). A weekly series whose day is not today shows no card line; the Progress page always lists it.
- **Escape now leaves Settings, Labels and Progress**, and Back or Escape return focus to where the page was opened from. The brief said "keyboard reachable like Settings and Labels, with Escape and Back returning focus", but the existing pages had no Escape handling. It was added for all three pages in `DesktopHome` (capture phase; not when a popover is open or focus is in a text field, select or contenteditable; a focused switch or button does not block it, `lib/editable.isTextEntryTarget`). cp9 pressed Escape on the Settings page body to prove keys change no task; Escape is removed from that loop (cp11 checks it instead).
- **Two strings were reworded** because my own banned wording test (which includes "behind" and "break") caught them: the Progress empty state is now "Repeating tasks show up here once you have used them for a few days." and the note is "A skipped day does not end a run." The test also caught a seed title in cp11 ("Broken run", renamed "Gap run"), which is why series titles must avoid the banned words on the Progress page.
- "Last 7 days: 5 of 6" counts done of SCHEDULED days, leaving skipped days and an open today out of the denominator; hidden when none were done (answer D).
- The marker list also includes the string `Show streaks` (so the setting label cannot reach the phone by accident).

## Time zones (addition 3)

`TZ` **does** take effect on this Windows Node: the test re-runs the DST walk in child processes with `TZ=Europe/London`, `America/New_York` and `Pacific/Auckland` over the spring and autumn changes of each, and a probe shows the offset really changed in 3 of 3 zones (printed as a diagnostic). So route 1 (real zones) was used. The fallback proof is also in the suite and always runs: a source test that `seriesStreak.ts` steps dates only with `kanban.addDays` and contains no millisecond arithmetic (no `86400000`, `24 * 60 * 60`, `getTime()`, `Date.now()`, `setTime(`). What I could not verify: other Node builds or a Mac, where `TZ` at run time may behave differently (the fallback proof still holds there).
